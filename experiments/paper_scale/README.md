# Paper scale experiments, 19 November 2026

The local checkout holds the primary data in `out/campaign`. Formal timing pairs one sequential process pinned to core 0 of s50's 9950X with its RTX 5090. Each setting alternates engine order, warms up once and records three complete process walls. A timeout, simulator error or first FCT mismatch closes that setting with the raw failure. The other settings still run. RX and a87 results validate correctness independently of the timing campaign.

## Scheduling and return

The local user service `twins-paper-scale-s50.service` polls the existing experiment queue. For the active parallel75 scheduler it checks the terminal receipt and its resource epoch against the last activity snapshot. For the earlier serial scheduler it checks the terminal receipt and its five quality receipts. Both schedulers use the same exclusive flock. The new worker holds the lock until the current job exits. A detached worker can outlive a dropped SSH connection. The controller checks each returned archive's SHA-256 before releasing the remote scratch directory. The queue uses `/home/cassius/Videos/twins-paper-scale-20261119` on s50 and `/home/cassius/netsim/twins-paper-scale-20261119` on a87. The user service resumes after reboot. See `out/campaign/s50/queue.jsonl` for the current state and `finished.json` for terminal receipts.

## Reproduction

- `freeze.py` builds the four FatTree sizes and freezes 20 existing web-search inputs. Ten cross-rack rounds give every host a send and a receive. TCP uses 32 KiB and IRN uses 150,000 bytes per flow. Seed 101 selects the permutations, seed 102 is the TCP holdout. Within each IRN incast round, eight sources per destination share the receiving host. The manifest lists the four link devices before profiling.
- `dcqcn_inputs.py` derives the formal IRN inputs. It explicitly enables switch ECN at 32/64 kB and probability 0.2 with DCQCN, one data priority, a 1 MiB switch pool and PFC disabled. The original anchor-derived series with switch ECN disabled remains in `inputs`. The author's explicit BDP parameter is 156,000 bytes on this scale fabric.
- `scale.py` checks ordered TCP fields or IRN per-flow identity, start and duration. `tcp_diag.py` records separate wide/compact, single-pass, retry and seed-holdout runs. Memory is sampled device-wide. Comparisons report the greater of the counts of non-padding runs inspected in the two histories. A truncated result gets its own bin. Instrumented timings are kept separate.
- `irn_diag.py` captures the specified devices and samples every 64th executed logical slot on a fixed grid starting at slot 2,000,000, across 256 possible points. `irn_report.py` sorts each physical device's serialized transmissions by time and compares all 14 fields. It computes the serial interval union and overlap with endpoint work on a common device clock. The denominator includes sampled device work, excluding launch and idle gaps. The active-port statistic counts arrivals or due transmission completions for each switch and slot with active ports.
- `ecn.py`, `ecn_gpu.py` and `first_mark.py` produce the 480 CPU cases, compare the original order's 80 GPU outputs, and isolate the first observed difference in CE for the same packet, queue and timestamp in the selected trace. Each arrival is its own paired unit.
- `oracle/` builds a scratch driver and links the same ASTRA frontend into the sequential author transport. The offline driver reads decimal flow start times rounded to their prescribed integer nanoseconds. The live SimAI adapter uses its four-byte sequence-header difference and integer wire serialization. `ai_stages.py` fixes both workload stages and varies only switch-buffer size. The GPU queue storage cap 65,536 accommodates the large-buffer control. `ai_witness.py` and `ai_cause.py` follow actual host transmissions, QP completion, ASTRA timers and the next send.
- `archive.py` compresses on a87, unpacks into a fresh directory and checks every archived file there. The local controller independently verifies the returned archive digest before publishing it in the local paper's `paper_data` directory.
