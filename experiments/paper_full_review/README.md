# TwiNS 全文复核补测

新实验用论文原先的输入和独立顺序参照。CPU 编译、短程 HPCC 及 stub 剖析可以在 a87 完成。HIP 在本机单 GPU 服务内运行，内存上限 28 GiB。CUDA 脚本沿用 s50 原有实验门禁和独占锁。每一批完成后用 `fetch_s50.sh` 回收原始文件和 SHA-256 清单。

| 实验 | 入口和验收证据 |
| --- | --- |
| RDMA 12 项原拒绝记录 | `dcqcn.py` 用 `dcqcn.json` 中的原路径、参数和参照摘要回放。每一项均核对完整 FCT 和按时间、端口稳定排列的 `wire.raw`。 |
| DCQCN 同刻事件 | `native_timer.py` 对已有 HPCC 库使用独立带日志对象，`minimize_timer.py` 对冻结 273 流输入做删减。`timer_compare.py` 以原生 FCT 的完成时刻截断每 QP 的语义范围，核对仍存活时的全部事件。 |
| 迟到数据 | `late_probe.sh` 用实际第二数据段的副本探测 QP 删除前后，并在同一时间安排删除之前和之后两种创建序。GPU 探针构建需 `RDMA_LIFETIME_PROBE`。同时核对两条 FCT 以及所有反馈包。 |
| 终态拒绝与重试 | `terminal.sh` 使用有界的正常入口。首遍和末遍日志分开判定，`rdma_regression.py` 读取冻结 176 项干净清单。固定尾环和自动扩容使用同一高历史深度的 DCTCP 负载。 |
| 16,000 主机队列容量 | `rdma_scale.py` 只增加明确报告溢出的端口，不修改负载或协议缓冲。原生紧凑初始化与先前规模实验的控制相同；同时对照原轻载和 8,192 主机。 |
| TCP 宽历史 | `tcp_timing.sh` 为初始固定版本的四档配对。`cuda_tcp_resume.sh` 为可按链路压缩到达环的版本。`tcp_timing.py` 区分默认重跑和直接宽历史，试跑外的三轮交错计时，并在小输入核对逐队列输出。 |
| NVLink 等待和闭环流表 | `ai_profile.py` 复用工作负载、拓扑和集合算法。记录最慢 worker 的发布时刻、协调器实际等待、复制、续取和有效输出量。冷跑与复用运行用完整消息和动作摘要核对。`stub_growth.py` 单列 CPU stub 的记录向量分配开销。 |
| PFC 端口回退 | `cuda_diagnostics.sh` 用 `RDMA_PFC_AUDIT` 汇总两个热点交换机的回退原因、实际发包端口和按设备时钟计的服务时间。检查和强制串行都用固定 8 MiB 负载及 6/64 MiB 池。 |

采样显存为进程观测值，显式设备分配和到达环字节独立报告。PFC 服务时钟为端口归并的设备工作量，各并发块的时钟累加不等于进程耗时。同一时钟的 worker 发布时刻用于解释协调器实际阻塞，未与它重复相加。
